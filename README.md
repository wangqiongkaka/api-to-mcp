# 接口工坊 · API-to-MCP

将公司 REST API 配置为可被 AI 客户端发现和调用的 MCP 工具。前端使用 Vue 3 + TypeScript，后端使用 Go，数据库使用 PostgreSQL，直接提供独立 MCP 服务。

**使用流程**：在接口库配置 HTTP 接口，保存草稿并调试，确认结果后发布。AI 客户端使用个人令牌连接工作台的 `/mcp` 地址，通过工具名称和参数调用已发布接口。

## 快速启动

以下命令在项目根目录执行。首次启动需要 Go 1.25.1 或更高版本生成本地配置，以及 Docker 和 Docker Compose 运行服务。

```bash
go run ./cmd/server -init
docker compose --profile full up -d --build --wait --wait-timeout 90
```

打开 <http://127.0.0.1:8088> 注册成员账户。管理员用户名默认是 `admin`，随机初始密码见本地 `.env` 的 `ADMIN_PASSWORD`。初始化命令以 `0600` 权限创建文件，已有 `.env` 时跳过初始化。更新应用可直接重跑上面的 Compose 命令。

工作台和 PostgreSQL 分别绑定本机端口 `8088` 和 `55432`，数据库保存在 Docker 卷中。供同事访问时，通过 HTTPS 反向代理暴露工作台，保留请求 Host，并设置 `COOKIE_SECURE=true`。

## 从接口配置到调试

### 1. 配置地址与参数映射

在「接口库」选择「新建接口」，填写工具名称、用途描述、请求方法和接口地址。先将上游源地址加入 [上游访问范围](#上游访问范围)。

- **参数位置**：上方「参数映射」配置查询参数、路径参数和请求头。路径变量写成 `{id}`，对应参数应设为固定值、必须传入或必须有值。数组和对象放在下方「JSON 请求体」中。
- **映射方式**：「客户端填写」的参数会进入调试表和 MCP 输入结构。「固定值」由服务端填写，客户端不能覆盖，适用于固定请求头等配置。
- **URL 查询参数**：点击「提取 URL 查询参数」可将地址里的查询项转为固定字符串参数，再逐项调整类型。保留在 URL 上的查询项会随请求发送，同名查询参数以参数表中的值为准。

### 2. 输入请求体并生成字段

例如，某个 POST 查询接口接受 IP 和负责人两种条件，至少要填一项。在「JSON 请求体」展开「输入请求体」，填入上游需要的结构。占位符是完整的 JSON 字符串，需要保留双引号。

```json
{
  "queryParams": [
    {"uniqueCode": "ip", "value": "{{host_ip}}"},
    {"uniqueCode": "owner", "value": "{{admin}}"}
  ]
}
```

点击「从占位符生成参数」，把生成的 `host_ip`、`admin` 均设为「数组」「客户端填写」「选填」，两行都勾选「筛选参数」。示例中的 `uniqueCode` 是上游字段标识，实际配置时使用接口定义的值。

**填写要求**作用于单个参数：

| 填写要求 | 调用规则 | 以数组参数为例 |
| --- | --- | --- |
| 选填 | 可以省略字段 | 调试时留空会省略该字段 |
| 必须传入 | 字段必须存在，值符合类型即可 | 可以传 `[]` |
| 必须有值 | 字段必须存在且包含有效值 | 省略、`[]`、`[""]` 都会被拒绝 |

**筛选参数**作用于勾选的整组字段。只要一个勾选项有有效值并实际进入上游请求，就满足筛选条件。未勾选的分页、数量等参数不能代替筛选条件。要实现“任选其一”，组内每个字段都设为「选填」。数值 `0` 和布尔值 `false` 都是有效值。

模板支持省略选填数组及其对应的条件项。其他类型的模板参数应使用固定值、「必须传入」或「必须有值」。若旧接口启用过完整请求体模式，需改用请求体模板并重新保存。

### 3. 保存草稿，在调试表填值

点击「保存草稿」，再点击「调试」。表格按配置类型生成输入控件，只展示客户端需要填写的参数。

- 字符串直接输入，整数和数值使用数字框，布尔值选择 `true` 或 `false`。超出安全整数范围 `±9007199254740991` 的业务 ID 应配置为字符串。
- 数组每行填写一个字符串，或粘贴完整 JSON 数组以保留数字、对象等元素类型。对象字段填写 JSON 对象。
- 对「必须传入」的字段，调试表可发送空字符串、空数组或空对象。数字和布尔字段仍需填写该类型的值。

在上述示例中，只在 `host_ip` 行填入 `192.0.2.1`，点击「发送请求」，上游收到：

```json
{"queryParams":[{"uniqueCode":"ip","value":["192.0.2.1"]}]}
```

两个筛选项都留空时，调试页提示「请填写 host_ip 或 admin」，请求在转发前被拦截。调试会真实访问上游，写操作会产生实际业务影响。

### 4. 核对输出并发布

编辑页的「原始响应」用于核对上游正文。若需精简或重命名返回字段，在「输出字段」从调试结果选择路径，或添加固定 JSON 值，再点击「预览自定义结果」复用本次响应。

| 输出配置 | 成功调用时的 MCP 结果 |
| --- | --- |
| 无输出字段 | 返回上游正文及 HTTP 状态等调用信息 |
| 配置了输出字段 | 返回映射后的业务 JSON，可对照调试页的「自定义结果」 |

响应路径使用 JSON Pointer。举例来说，`/data/users/0/id` 取第一条记录的 ID，`/data/list/*/totalIp` 提取每条记录的 IP。键名里的 `~` 和 `/` 分别写成 `~0` 和 `~1`。所选路径缺失或需要提取的正文无法解析时，会提示映射失败。上游非 2xx 响应保留原状态码和正文。

确认后保存并点击「发布工具」。发布后需先停用才能编辑。所有者和管理员可预览、下载面向原上游接口的 OpenAPI 配置，导出文件可能包含固定凭据。

## 上游访问范围

只有 `.env` 中 `UPSTREAM_ORIGINS` 列出的源地址能被发布或调用：

```dotenv
UPSTREAM_ORIGINS=https://api.example.com
```

每项必须是完整的协议、主机及可选端口，不能使用通配符、路径或账号信息。修改后需重启 Go 服务。不会使用系统 HTTP 代理，不跟随上游重定向；默认超时 15 秒，允许配置 1–60 秒，响应限制为 2 MiB，不自动重试写请求。

## 连接 MCP 客户端

1. 发布自己的工具，或确认管理员已发布并共享需要调用的公共工具。
2. 打开“连接与令牌”，创建个人访问令牌并立即保存；完整值只展示一次。
3. 在支持 Streamable HTTP 的客户端中配置地址和请求头：

```text
地址：http://127.0.0.1:8088/mcp
请求头：Authorization: Bearer <个人访问令牌>
```

客户端可通过 `tools/list` 发现工具，再通过 `tools/call` 调用。自有工具沿用配置名称，其他用户共享的工具使用 `<名称>.public.<接口编号>`，同名工具可以同时使用。工具列表每次从数据库读取，发布、停用、共享变更及令牌撤销在后续请求生效。上游非 2xx 响应作为 MCP 工具错误返回，同时保留状态码和响应正文。

以上面的查询接口为例，MCP 客户端传入的工具参数是 `{"host_ip":["192.0.2.1"]}`。服务端负责组装 `queryParams`。调试与 MCP 使用相同的参数校验和请求构造逻辑。筛选项全空时，MCP 返回带 `isError: true` 的工具结果和对应提示，上游不会收到请求。

成员管理自己的工具。管理员可管理全部接口，并将自己维护的工具设为公共。其他成员可以调用已发布的公共工具，完整定义和导出权限保留给所有者和管理员。接口定义以 AES-256-GCM 加密存储。

管理员停用成员时，会撤销其全部会话和 MCP 令牌；重新启用账户后，需要重新登录和创建令牌。

## 本地开发

安装 Go、Node.js 24 和项目依赖。使用本机进程运行后端时，先停止占用 `8088` 的容器应用，保留数据库：

```bash
docker compose --profile full stop app
docker compose up -d --wait db
npm --prefix web ci
npm --prefix web run build
go run ./cmd/server
```

保持后端运行，在另一终端执行 `npm --prefix web run dev`，打开 <http://127.0.0.1:5178>。Vite 会将 `/api` 和 `/mcp` 代理到 Go 服务。

## 验证

```bash
go test ./...
go vet ./...
npm --prefix web run build
```

PostgreSQL/MCP 集成测试使用独立测试数据库，并在随机 schema 中运行，结束后只删除该 schema：

```bash
docker compose exec -T db createdb -U api_mcp api_to_mcp_test
# 使用测试数据库连接串，数据库名必须以 _test 结尾。
TEST_DATABASE_URL='postgres://api_mcp:<DB_PASSWORD>@127.0.0.1:55432/api_to_mcp_test?sslmode=disable' go test -race ./... -count=1
```

未提供 `TEST_DATABASE_URL` 时，集成测试会明确跳过。端到端浏览器测试见 [web/e2e](web/e2e)：

```bash
cd web
npx playwright install --only-shell chromium
npm run build
npx playwright test
```

浏览器测试始终无界面运行，自动启动独立测试后端 `8089` 和模拟上游 `8099`，使用 `_test` 数据库，不使用工作台的正式数据库。测试会写入账户和接口数据，请使用专用测试库。

## 结构与复用

```text
cmd/server/          启动、环境配置初始化
internal/platform/  账户、加密存储、接口定义、HTTP 映射、MCP 和导出
web/                Vue 3 + TypeScript 工作台
compose.yaml        PostgreSQL 与完整容器部署配置
DESIGN.md           界面规范
```

## 当前边界

- 首版包含管理员和成员两种角色，不含 SSO、组织分组、审批和账户找回。
- 账户可以自行注册；能注册不代表能访问任意网络，上游源地址仍由部署者控制。
- MCP 使用静态个人 Bearer 令牌，未实现 OAuth 授权流程；客户端需支持自定义认证请求头。
- 不自动请求接口来猜测类型、业务语义或响应 schema。
- 工具以 JSON 对象请求体为主，不支持 multipart 文件上传、流式大响应和任意模板执行。
- 登录限流为单进程内 IP 限流，多实例部署需要共享限流。Origin 校验依赖反向代理保留 Host。
- 请备份数据库与 `ENCRYPTION_KEY`；丢失密钥后无法恢复已加密的接口配置。修改 `.env` 的初始管理员密码不会重置已存在账户。
- 导出可能包含固定凭据。
- 内置 Pod 查询示例依赖公司内网，上游地址、凭据和连通性需按部署环境配置。
